# Registration: the line-first rune and the line-column coincidence profile (2026-10-30, before any run)

**Trigger.** The selection lane (§63) registered Q3, "no rule's pooled IoC z ≥ 4 against the per-page shuffle null", and it failed on one rule of 75: the first rune of each line (594 positions on the 55 unsolved pages) has pooled IoC 1.090, z +7.1. The post-hoc look recorded in §63: the pooled line-first distribution differs from the pages' own (χ² 78.7 on 28 df; EA, P, D, H, IA over, R, I, O, N, B under), for the 206 lines that begin a word (IoC 1.20) and the 388 that begin mid-word (1.06) alike; the last rune of each line is at null (0.998); its transliteration reads as nothing. Under a key that is uniform at every position no position class can carry a skewed distribution. So either the key is not uniform at line starts (a key that restarts at each line, or depends on the position within the line), or the line-initial glyphs are special (decorated or enlarged initials read differently; the blind re-reading left drop caps unread), or the transcription's line breaks are not independent of the runes. The ledgers cover per-line key resets only for four named keys (`results/ledger_diff.md`, §34's schedules); a key-agnostic column test has not been run here or, as far as the ledgers show, elsewhere.

**Test** (`src/line_column.py`). Columns j = 0…15 from the line start and 0…5 from the line end, on the 55 unsolved pages with `/` as the line break. Per column: the pooled IoC (× 29) over all pages, and the within-page same-column coincidence count summed over pages; null: 2,000 shuffles of the runes within each page that keep the line lengths; z for each statistic. Variant: the first line of each page removed (the 55 page-initial runes are the drop-cap candidates). The column-0, 1 and 2 streams printed in transliteration.

**Readings and what each predicts.** (i) A key that restarts at every line with the same sequence on every page: every column elevated, pooled and within page. (ii) A key that restarts at every line with a page-specific sequence: every column elevated within page, pooled flat. (iii) A line-initial glyph or transcription effect: column 0 only, in both statistics, and the from-end columns flat. **Expected: (iii)**, because the over-represented runes are shared across pages (which (ii) forbids) while nothing in §55's position statistics or the every-k-th rules of §63 showed the later columns raised (which (i) requires).

**Claims.** R1: column 0 pooled z ≥ 4 (the Q3 failure restated on this instrument). R2: columns 1–5, pooled and within page, |z| < 3 in each of the ten cells; the claim fails if any cell reaches 4 or two reach 3. R3: column 0 keeps z ≥ 4 with the first line of each page removed. R4: the from-end columns 0–5 satisfy the R2 rule. If R2 fails, a line-structured key is alive and the next registration, before any decode is read, is the per-column shift recovery (each column's 29 shifts against English unigrams, with planted controls, which is the classical attack on a line-periodic key). If R3 fails, the effect is the page-initial glyphs and goes to the transcription against the page images. If R1–R4 hold, the finding is a line-initial glyph effect of unknown origin: descriptive, and the line-initial glyphs go to the page images next.

**Budget.** Minutes.
